📷 ESP32-CAM — how config is supposed to work

Optimal / standard pattern for this fleet:

  1. One firmware binary for all cameras (no per-device rebuild).
  2. Defaults live in NVS (Arduino Preferences namespace camcfg): ap_ssid, ap_pass, st_ssid, st_pass, name, admin. Compile-time defaults are only the first-boot seed (e.g. Mantis_1_Hotspot / mantis33).
  3. After flash, change identity at runtime:
    • POST /config with body fields + header X-Admin-Pass (device reboots into new SoftAP), or
    • Core2 WiFi screen / Manager UI.
  4. Do not bake a different SSID into the binary for every unit — that forces a unique build per camera and breaks the web flasher story.
Why not configure SSID inside the web flasher binary itself? Browser flashers (esp-web-tools) write firmware images. Per-device NVS images can be generated, but that needs a host tool (nvs_partition_gen / Python) and exact partition offsets. Runtime /config + NVS is simpler, standard on ESP32, and matches your existing Manager firmware.

Provision checklist

  1. Flash the same CAM fleet binary (or Manager-generated image) on every unit.
  2. Power the cam — it opens SoftAP with the baked defaults.
  3. Join that AP from phone/Core2, open http://192.168.5.1/.
  4. Set permanent SoftAP SSID / name / admin via /config (or Manager).
  5. On Core2: Cameras → Scan — new hotspot appears; tap to switch profile.

Suggested SoftAP naming

Use a predictable prefix so Core2 scan auto-picks them up:

  • Mantis_1_Hotspot
  • Mantis_2_Hotspot
  • Mantis_Kitchen

Default password for new scan entries: mantis33 (edit on Core2 WiFi screen if different).

AP IP stays 192.168.5.1 unless you change SoftAP config in firmware.
